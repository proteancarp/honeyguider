Register a service

The registration file is JSON you host anywhere an agent can fetch it — any HTTPS URL, IPFS, or a data: URI stored on-chain; the spec does not mandate a path. services lists the endpoints you want callers to use. The names below are examples rather than a fixed set — the spec leaves the number and type of endpoints to you, and wallet entries for other chains are common. Set x402Support to true if those endpoints accept x402 payments. registrations is what lets a caller check that the file and the on-chain entry agree, which is the cross-domain verification described above. You only learn the agent ID once the registration is mined, so the order is: publish the file without registrations, register, then update the file with the ID it returned. For an IPFS or data: URI, adding the ID changes the URI, so point the registry at the new one with setAgentURI(agentId, newURI).
